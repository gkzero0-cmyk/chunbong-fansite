# 춘봉 콘텐츠 아카이브 디자인 명세

작성일: 2026-09-22  
대상 저장소: `gkzero0-cmyk/chunbong-fansite`  
작업 브랜치: `feat/chunbong-content-archive`

## 1. 목적

팬사이트에 `춘봉 콘텐츠`를 추가해 춘봉이 직접 주최·기획·개최한 콘텐츠를 장기 보존 가능한 아카이브로 제공한다.

핵심 목표는 다음 세 가지다.

1. **보기 좋음** — 글만 나열하지 않고 대표 이미지, 포스터, 영상 썸네일, 타임라인 이미지를 적극 활용한다.
2. **찾기 쉬움** — 콘텐츠명·연도·카테고리·참가자 기준으로 빠르게 찾고, 상세 페이지에서 시작부터 종료까지 흐름을 이해할 수 있게 한다.
3. **데이터 신뢰성** — 공식 1차 자료를 우선하고, 출처·확인 상태·충돌 여부를 내부적으로 관리해 자료가 섞이거나 잘못 확정되는 일을 줄인다.

초기 범위는 **춘봉이 직접 주최·기획·개최한 콘텐츠**다. 단순 참가 콘텐츠는 이번 범위에서 제외하고 추후 별도 분류로 확장 가능하게 데이터 모델만 열어 둔다.

## 2. 현재 사이트 구조와 통합 원칙

현재 팬사이트는 정적 HTML/CSS/JS를 중심으로 `site-shell.js`, `styles.css`, `site-design-system.css`를 공유하고, 서버 기능은 단일 `api/content.js` 라우터와 `lib/*` 모듈을 통해 처리한다. 운영자 센터는 `operator.html`, `operator.js`, `lib/operator-center-api.js`와 기존 인증 세션을 사용한다.

따라서 새 기능은 별도 프레임워크나 별도 앱을 만들지 않는다.

- 공개 페이지: `chunbong-contents.html`
- 공개 스타일: `chunbong-contents.css`
- 공개 런타임: `chunbong-contents.js`
- 데이터/API 로직: 기존 `api/content.js` 라우터에 신규 타입/액션을 연결
- 운영자 관리: 기존 `operator.html` 탭에 `콘텐츠 아카이브` 추가
- 운영자 런타임: `operator.js`에 관리 기능 추가하되 가능하면 별도 모듈 `operator-contents.js`로 분리
- 공통 디자인: `site-design-system.css`의 색상·텍스트 계층·페이지 셸을 재사용
- 기존 `content.js`와 이름이 겹치지 않도록 신규 파일은 모두 `chunbong-contents.*` 명칭 사용

Vercel 함수 수를 늘리지 않기 위해 새 독립 서버리스 함수는 만들지 않고 기존 `api/content.js` 디스패치 구조 안에 추가한다.

## 3. 사용자 화면 정보 구조

### 3.1 상단 메뉴

공통 내비게이션에 `춘봉 콘텐츠` 항목을 추가한다.

권장 위치:
- 데스크톱 그룹: `기록` 그룹 안에서 `방송 이력` 앞 또는 뒤
- 모바일/전체 메뉴: 독립 메뉴 카드로 노출
- 홈 `전체 메뉴 보기`에도 `춘봉 콘텐츠` 바로가기 추가

페이지 식별자는 `body[data-page="contents"]`, 내비게이션 식별자는 `data-nav="contents"`를 사용한다.

### 3.2 아카이브 목록 화면

첫 화면은 이미지 중심의 카드 그리드다.

상단 구성:
- 제목: `춘봉 콘텐츠`
- 설명: 춘봉이 직접 만들고 주최한 콘텐츠의 기록을 모아보는 공간
- 검색 입력
- 카테고리 필터: 전체 / 마인크래프트 / 노래대회 / 방송 기획 / 클래스·이벤트 / 기타
- 연도 필터
- 정렬: 최신순 / 오래된순

콘텐츠 카드 표시 정보:
- 16:9 대표 이미지
- 콘텐츠명
- 카테고리
- 진행 기간
- 춘봉 역할
- 상태 배지: 모집 / 진행 중 / 종료
- 1~2줄 요약
- 상세보기 진입

PC는 2~3열, 태블릿 2열, 모바일 1열을 기본으로 한다.

### 3.3 상세 화면

별도 HTML을 콘텐츠마다 만들지 않고 `chunbong-contents.html?id=<slug>` 형태로 같은 화면에서 렌더링한다.

상세 화면 순서:

1. **히어로**
   - 대표 이미지
   - 콘텐츠명
   - 기간
   - 카테고리
   - 춘봉 역할
   - 상태
   - 간단한 소개

2. **핵심 요약**
   - 개최 기간
   - 참가 규모
   - 자료 수
   - 영상 수
   - 공식 출처 수
   - 최종 확인일

3. **탭/섹션**
   - 소개
   - 타임라인
   - 영상
   - 게시글
   - 참가자·결과
   - 이미지

4. **출처 안내**
   - 사용자에게 필요한 범위에서 공식/보조 출처를 명확하게 보여준다.

## 4. 이미지 중심 UX

이미지는 장식이 아니라 자료의 일부로 취급한다.

### 4.1 이미지 역할

- **대표 이미지**: 목록 카드와 상세 히어로에 사용
- **타임라인 썸네일**: 공지·방송·결과 등의 개별 기록에 사용
- **영상 썸네일**: VOD, Catch, 클립, YouTube, Shorts
- **갤러리 이미지**: 포스터, 서버 화면, 행사 장면, 결과 이미지 등

### 4.2 이미지 표시 원칙

- 목록/영상 썸네일은 기본 16:9
- 원본 비율이 다른 포스터는 카드에서 `object-fit: cover`로 미리보기하되 상세 확대 시 원본 비율 유지
- 원본 이미지 파일 자체를 재압축하거나 저화질로 교체하지 않는다
- 비핵심 이미지는 `loading="lazy"`, `decoding="async"`
- 첫 대표 이미지만 우선 로딩 후보
- 외부 공식 썸네일은 원문 URL을 저장하되, 운영자가 직접 업로드한 이미지 또는 팬사이트 보유 자산은 `assets/chunbong-contents/` 아래 원본 보존
- 이미지 실패 시 카드가 깨지지 않도록 텍스트 기반 폴백 UI 제공

### 4.3 확대 보기

갤러리와 포스터는 클릭 시 라이트박스로 확대한다.

- 화면 안에 맞춰 표시
- 원본 비율 유지
- ESC/닫기 버튼/배경 클릭 지원
- 모바일에서도 화면 밖으로 넘치지 않음
- 확대 상태에서 원문 자료 링크 제공 가능

## 5. 자료 유형

모든 기록은 유형을 가진다.

- `notice` — 모집/공지
- `post` — 방송국 게시글
- `vod` — 다시보기
- `catch` — SOOP Catch
- `clip` — 클립
- `youtube` — YouTube 영상
- `shorts` — YouTube Shorts
- `article` — SOOP PICK 등 외부 기사
- `result` — 결과/수상/종료 기록
- `image` — 포스터·스크린샷·기념 이미지
- `reference` — 나무위키 등 보조 기록

화면에서는 아이콘과 텍스트 배지를 함께 사용해 색만으로 구분하지 않는다.

## 7. 출처와 정확성 정책

### 7.1 출처 우선순위

정보를 확정할 때 아래 순위를 기본으로 한다.

1. 춘봉 SOOP 방송국의 공식 게시글·공지
2. SOOP 원본 VOD / Catch / 클립
3. 춘봉 공식 YouTube
4. 콘텐츠 관계자의 공식 게시물
5. SOOP PICK 등 플랫폼 기사
6. 나무위키 등 외부 정리 자료

나무위키는 자료 발견과 교차 확인에는 활용하지만, 1차 자료와 충돌할 경우 자동으로 우선하지 않는다.

### 7.2 확인 상태

운영자 화면에서는 자료별로 다음 상태를 관리한다.

- `official` — 1차 공식 자료 직접 확인
- `cross_checked` — 복수 자료에서 일치
- `needs_review` — 추가 확인 필요

공개 페이지에서는 내부 등급을 과도하게 노출하지 않되, 불확실한 날짜나 결과를 확정값처럼 쓰지 않는다.

### 7.3 날짜 정밀도

정확한 날짜를 알 수 없으면 억지로 날짜를 생성하지 않는다.

- `day`: 2026-06-24
- `month`: 2026-06
- `year`: 2026
- `unknown`: 확인 중

화면에서는 각각 `2026년 6월 24일`, `2026년 6월`, `2026년`, `날짜 확인 중`으로 출력한다.

### 7.4 정보 충돌

동일 필드에 서로 다른 값이 들어오면 자동 확정하지 않는다.

운영자 센터에 `정보 충돌`로 표시하고:
- 후보 값
- 각 값의 출처
- 원문 링크
- 확인 날짜

를 비교한 뒤 운영자가 최종값을 지정한다.

## 8. 서버/API 및 저장 방식

### 8.1 공개 데이터

공개 페이지는 기존 `/api/content` 라우터를 통해 공개용 콘텐츠 목록/상세 데이터를 가져온다.

예시:
- `/api/content?type=chunbong-contents`
- `/api/content?type=chunbong-content&id=leopel`

응답에는 **published=true인 자료만** 포함한다.

### 8.2 저장소

기존 운영자 센터가 사용하는 Redis/KV 계층을 재사용한다.

권장 키:
- `content-archive:index:v1`
- `content-archive:item:v1:<id>`
- `content-archive:draft:v1:<id>`
- `content-archive:audit:v1`

초기 데이터가 없거나 KV 장애가 있을 때 페이지가 완전히 비지 않도록 검증된 최소 정적 시드 데이터를 둘 수 있다. 정적 시드는 `chunbong-contents-seed.js` 또는 JSON으로 분리한다.

### 8.3 캐시

공개 목록/상세는 짧은 TTL로 캐시해 반복 탐색 시 빠르게 연다.

- 목록: 5분 안팎
- 상세: 5분 안팎
- 운영자 저장 직후 해당 키 캐시 무효화

## 9. 운영자 센터

기존 운영자 인증을 그대로 사용한다.

새 탭: `콘텐츠 아카이브`

기능:
- 새 콘텐츠 생성
- 콘텐츠 수정
- 공개/비공개
- 대표 이미지 설정
- 카테고리/상태/기간 설정
- 참가자/결과 편집
- 타임라인 항목 추가·정렬·수정
- VOD/Catch/클립/YouTube/Shorts 링크 추가
- 이미지 갤러리 관리
- 출처 링크 추가
- 확인 상태 관리
- 중복 자료 표시/병합
- 정보 충돌 확인
- 미리보기
- 공개 전 검증

운영자 편집은 자동 공개하지 않는다.

흐름:
`자료 입력 → 초안 저장 → 검증 경고 확인 → 미리보기 → 공개`

## 10. 반자동 자료 수집 원칙

초기 버전은 무분별한 자동 크롤링/자동 게시를 하지 않는다.

자료 후보 탐색 기능을 추가할 경우:
- 후보 링크와 기본 메타데이터만 제안
- 운영자가 확인하기 전 공개 데이터에 포함하지 않음
- 동일 URL/동일 영상 ID 중복 감지
- 제목이 비슷해도 자동 병합하지 않음

외부 자료 수집이 실패해도 기존 공개 아카이브는 그대로 유지한다.

## 11. 홈 연결

홈 `바로가기` 또는 `전체 메뉴 보기`에 `춘봉 콘텐츠`를 추가한다.

초기에는 전체 메뉴 영역에 추가하고, 데이터가 충분히 쌓이면 별도 대표 섹션을 추가할 수 있다.

대표 섹션 확장 시:
- 최신 또는 대표 콘텐츠 3개
- 대표 이미지
- 기간
- 한 줄 소개
- `전체 콘텐츠 보기 →`

## 12. 디자인 시스템

현재 팬사이트의 어두운 배경과 주황색 핵심 브랜드는 유지한다.

신규 페이지 전용 포인트 컬러는 기존 색상 체계에 추가하되, 정보 유형은 색만으로 전달하지 않는다.

권장 톤:
- 카드: 낮은 대비의 검정/짙은 회색
- 테두리: 현재 디자인 시스템 수준
- 제목: `--text-primary`
- 본문: `--text-secondary`
- 메타: `--text-muted`
- 핵심 버튼/활성 상태: 춘봉 오렌지
- 영상/공지/이미지 자료 유형은 작은 배지와 아이콘으로 구분

화려한 글로우·과도한 애니메이션은 사용하지 않는다. hover는 이동 1~2px, 테두리/배경 변화 정도로 제한한다.

라이트 테마도 기존 변수 체계에 맞춰 지원한다.

## 13. 모바일/접근성

- 760px 이하에서 카드 1열
- 필터는 접히거나 가로 넘침 없이 재배치
- 탭은 좁은 화면에서 2줄 또는 선택형 UI로 변경
- 라이트박스가 viewport를 넘지 않음
- 버튼/링크 터치 영역 44px 안팎 확보
- 이미지 alt 필수
- 아이콘만 있는 버튼에는 aria-label
- 키보드로 필터, 카드, 탭, 라이트박스 조작 가능
- prefers-reduced-motion 존중

## 14. 검색/필터

클라이언트 필터 기준:
- 콘텐츠명
- 별칭
- 참가자
- 연도
- 카테고리

검색 결과 수를 표시하고, 결과가 없을 때 빈 상태 UI를 제공한다.

필터 상태는 가능하면 URL query에 반영해 공유/뒤로가기가 자연스럽게 동작하게 한다.

## 15. 오류 처리

- API 실패: 정적 시드 또는 친절한 빈 상태
- 이미지 실패: placeholder
- 외부 링크 제거/404: 운영자 화면에서 점검 대상으로 표시
- 잘못된 콘텐츠 ID: 목록으로 돌아갈 수 있는 404형 상태
- 불완전 데이터: 해당 필드만 숨기고 전체 페이지는 유지
- 외부 자료를 불러오는 동안 스켈레톤 사용, 무한 로딩 금지

## 17. 초기 데이터 등록 정책

첫 배포에서는 많은 항목을 억지로 채우지 않는다.

우선순위:
1. 공식 자료를 충분히 확인할 수 있는 대표 콘텐츠부터 등록
2. 각 콘텐츠는 최소 1개 이상의 1차 출처를 가져야 공개 가능
3. 대표 이미지 출처를 확인
4. 정확하지 않은 참가자/결과는 비워 둠
5. 나무위키 단독 정보는 `needs_review` 후보로만 관리

초기 대표 후보는 레오펠, 그냥서버, 춘봉 주최 노래대회 등으로 두되, 실제 공개 레코드는 구현 시 SOOP/YouTube/공식 자료를 다시 조사해 검증된 항목만 넣는다.
