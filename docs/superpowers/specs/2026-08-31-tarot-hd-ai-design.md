# 춘봉 팬사이트 고화질 + AI 타로 업그레이드 설계

## 목표

기존 TAROT 페이지의 78장 풀덱, 직접 카드 선택, 정방향/역방향, 1장/3장 스프레드는 유지하면서 다음 두 가지를 추가한다.

1. 현재 192×288 수준으로 압축된 카드 시트 때문에 발생하는 흐릿한 결과 이미지를 원본 기반 고화질 카드 이미지로 교체한다.
2. 사용자가 뽑은 실제 카드와 질문을 바탕으로 OpenAI Responses API가 자연스러운 한국어 상담형 리딩을 생성하도록 한다.

기존 공지, CATCH, 다시보기 등 다른 팬사이트 기능은 건드리지 않는다.

## 현재 상태와 문제

- 카드 원본은 메이저 22장 + 마이너 56장 = 78장이다.
- 메이저는 21장이 1024×1536, 1장이 1055×1491이고 마이너 56장은 모두 1024×1536이다.
- 현재 사이트는 카드 13장을 한 시트에 넣은 저해상도 AVIF 데이터 URI를 6개 JavaScript 파일로 로드한다.
- 결과 화면은 `background-size: 1300% 100%`와 `background-position`으로 한 칸을 확대 표시한다.
- 카드 한 장의 실질적인 표시 원본이 약 192×288이기 때문에 데스크톱 결과 카드에서 크게 확대하면 눈에 띄게 흐려진다.
- 현재 `tarot-data.js`는 브라우저와 CommonJS 둘 다 지원하므로 새 서버 API에서도 동일한 78장 데이터셋을 재사용할 수 있다.

## 접근 방식 비교

### A. 권장: 개별 고해상도 카드 + 서버리스 AI API

- 78장을 각각 고해상도 WebP로 저장한다.
- 결과에서 실제 선택된 1장 또는 3장만 브라우저가 요청한다.
- 카드 이미지는 CSS 배경이 아니라 실제 `<img>` 요소로 표시한다.
- AI는 Vercel Serverless Function에서 OpenAI Responses API를 호출한다.

장점: 가장 선명하고, 첫 페이지 로딩이 가볍고, API 키가 노출되지 않으며 유지보수가 명확하다.
단점: 저장소에 78개 이미지 파일이 추가된다.

### B. 고해상도 스프라이트 시트 유지

- 6개의 큰 이미지 시트를 고해상도로 다시 만든다.

장점: 파일 수가 적다.
단점: 카드 한 장을 보기 위해 13장짜리 큰 이미지를 내려받아야 하고, 배경 위치/스케일링에 계속 의존한다. 디코딩 메모리도 커진다.

### C. 브라우저에서 원본을 직접 압축/가공

- 원본 대형 이미지를 배포하고 브라우저에서 축소한다.

장점: 구현 단순.
단점: 네트워크 사용량이 지나치게 크고 모바일 성능이 나쁘다.

**선택: A.**

## 고화질 카드 자산 설계

### 출력 형식

- 경로: `assets/tarot/hd/<card-id>.webp`
- 기본 최대 해상도: 원본 기준 최대 1024px 폭 유지
- 인코딩: WebP 고품질 설정을 사용하되 카드 텍스트/테두리가 뭉개지지 않는 품질로 생성한다.
- 원본보다 확대하지 않는다.
- 비표준 비율의 메이저 1장은 비율을 보존하며 강제 크롭하지 않는다.

### 로딩 방식

- 카드 선택 전에는 앞면 이미지를 로드하지 않는다.
- 선택이 완료된 결과 화면에서 1장 또는 3장만 `img`로 로드한다.
- `loading="lazy"`, `decoding="async"`를 사용한다.
- 결과 카드 래퍼가 정/역방향 회전을 담당하고 실제 이미지에는 임의 크롭을 하지 않는다.
- 이미지 로드 실패 시 기존의 텍스트 fallback을 표시한다.

### 데이터 변경

`tarot-data.js`의 각 카드에는 다음 필드를 추가하거나 기존 이미지 시트 필드를 교체한다.

```js
imagePath: 'assets/tarot/hd/major-00.webp'
```

기존 `imageSheet`/`imageSlot`은 새 렌더링 경로에서는 더 이상 사용하지 않는다. 기존 저해상도 시트 파일은 새 고화질 자산 검증 후 제거한다.

## AI 타로 상담 사용자 흐름

1. 사용자가 기존과 동일하게 주제, 카드 수, 3장 스프레드, 질문을 선택한다.
2. 카드 1장 또는 3장을 직접 뽑는다.
3. 즉시 기존의 로컬 기본 해석을 보여준다. 이 단계는 무료이며 OpenAI 장애와 무관하게 항상 작동한다.
4. 결과 영역 아래에 `AI 타로 상담 받기` 버튼을 표시한다.
5. 사용자가 버튼을 눌렀을 때만 서버 API를 호출한다.
6. 생성 중에는 버튼을 비활성화하고 로딩 상태를 표시한다.
7. 성공 시 `AI 상담 리딩` 영역에 카드별 해석, 전체 흐름, 현실적인 조언, 한줄 정리를 표시한다.
8. 성공한 동일 리딩에서는 중복 API 호출 버튼을 숨기거나 비활성화한다. 새 카드를 뽑으면 다시 상담할 수 있다.
9. API 실패 시 기존 기본 해석은 유지하고 AI 영역에 재시도 버튼과 오류 안내만 표시한다.

자동 호출을 하지 않는 이유는 사용자가 원할 때만 비용을 발생시키고, 기본 타로 기능의 독립성과 신뢰성을 유지하기 위해서다.

## 서버 API

### 파일

`api/tarot-reading.js`

### 메서드

- `POST`만 허용
- `Content-Type: application/json`

### 요청 형식

```json
{
  "question": "지금 준비 중인 일을 계속 밀어도 괜찮을까?",
  "topic": "concern",
  "spreadId": "situationAdviceOutcome",
  "cards": [
    {"id":"major-16","orientation":"upright","position":"상황"},
    {"id":"major-17","orientation":"upright","position":"조언"},
    {"id":"cups-03","orientation":"reversed","position":"결과"}
  ]
}
```

### 서버 검증

클라이언트가 보낸 카드명이나 해석 문장은 신뢰하지 않는다.

서버는 `require('../tarot-data.js')`로 공식 78장 데이터를 읽고 다음을 검증한다.

- `topic`이 허용된 주제인지
- `spreadId`가 허용된 스프레드인지
- 카드 수가 정확히 1장 또는 3장인지
- 각 카드 ID가 78장 데이터에 실제 존재하는지
- 카드가 중복되지 않는지
- orientation이 `upright` 또는 `reversed`인지
- position이 선택한 스프레드의 실제 위치와 순서가 맞는지
- 질문 길이가 500자를 넘지 않는지

검증이 끝난 뒤 서버가 공식 카드명, 키워드, 정/역방향 의미를 다시 조립해 OpenAI에 전달한다.

## OpenAI 호출 설계

### API

- OpenAI Responses API 사용
- API 키: `OPENAI_API_KEY`
- 모델: `OPENAI_TAROT_MODEL` 환경변수로 오버라이드 가능
- 기본 모델: `gpt-5.6-luna`

`gpt-5.6-luna`는 비용 민감한 고빈도 텍스트 워크로드에 맞는 최신 GPT-5.6 계열이며 Responses API와 구조화 출력을 지원한다. 타로 리딩은 긴 복잡 추론보다 자연스러운 한국어 요약과 상담 문장 품질이 중요하므로 기본값으로 적합하다. 필요하면 `gpt-5.6-terra` 또는 `gpt-5.6-sol`로 설정만 바꿀 수 있다.

### 호출 제한

- 도구 호출 없음
- 웹 검색 없음
- 카드 이미지를 모델에 보내지 않음
- 서버가 확정한 카드 텍스트 정보만 입력
- reasoning effort는 낮게 유지
- 출력 길이는 약 700~900 토큰 수준으로 제한
- 한 번의 카드 결과에서 성공한 AI 호출은 프론트에서 재호출하지 않음

### AI 리딩 원칙

시스템 지침은 다음을 요구한다.

- 자연스러운 한국어 상담자 말투
- 뽑힌 카드와 정/역방향을 모두 반영
- 3장에서는 각 위치의 의미를 구분
- 질문 맥락을 반영하되 운명을 확정적으로 단언하지 않음
- 불안 조장, 공포 조장, 과도한 확신을 피함
- 건강, 법률, 투자 등 고위험 주제에서 전문 진단/확정적 예측을 하지 않음
- 실제 선택 가능한 행동이나 점검 포인트를 제시
- 타로를 자기성찰과 참고용 도구로 표현

### 구조화 응답

서버에서 프론트로 다음 구조를 반환한다.

```json
{
  "reading": {
    "title": "이번 카드가 보여주는 흐름",
    "overall": "...",
    "cards": [
      {"id":"major-16","position":"상황","reading":"..."}
    ],
    "advice": ["...", "..."],
    "summary": "한줄 정리..."
  },
  "model": "gpt-5.6-luna"
}
```

프론트는 모델이 만든 HTML을 직접 삽입하지 않는다. 텍스트 필드만 렌더링해 XSS 위험을 차단한다.

## 개인정보와 저장

- 질문과 카드 결과를 데이터베이스에 저장하지 않는다.
- API 함수에서 질문 본문을 `console.log`하지 않는다.
- 브라우저 localStorage에도 상담 내용을 기본 저장하지 않는다.
- OpenAI API 키는 클라이언트 JavaScript나 HTML에 절대 포함하지 않는다.

## 오류 처리

- 400: 잘못된 질문/카드/스프레드 데이터
- 405: POST 이외 요청
- 503: `OPENAI_API_KEY` 미설정
- 429: OpenAI 사용량/속도 제한
- 502: OpenAI 호출 실패 또는 예상치 못한 응답

프론트 오류 메시지는 기술적인 내부 내용을 그대로 노출하지 않고 `AI 상담을 불러오지 못했습니다. 기본 해석은 그대로 이용할 수 있습니다.`를 기본 문구로 사용한다.

API 키가 아직 Vercel 환경변수에 없으면 기본 타로는 계속 정상 작동하고 AI 버튼은 서버의 503 응답을 사용자 친화적으로 처리한다.

## 비용 제어

- AI는 사용자가 버튼을 눌렀을 때만 호출
- 한 리딩당 성공 호출 1회
- 질문 최대 500자
- 카드 최대 3장
- 출력 길이 제한
- 기본 모델을 `gpt-5.6-luna`로 설정
- 향후 필요하면 Vercel/외부 저장소 기반 rate limiting을 별도 기능으로 추가할 수 있지만 이번 범위에는 영속 저장소를 새로 도입하지 않는다.

## 프론트엔드 UI

`tarot.html` 결과 영역에 AI 상담 패널을 추가한다.

상태:

1. **준비** — `AI 타로 상담 받기` 버튼
2. **로딩** — 스피너 또는 점 애니메이션 + `카드를 읽고 있어요...`
3. **성공** — 전체 리딩 / 카드별 상담 / 조언 / 한줄 정리
4. **오류** — 오류 안내 + 실패한 경우에만 `다시 시도`

기존 검정/주황 테마를 유지하고 AI 영역은 기존 `tarot-summary`와 시각적으로 구분되는 패널로 만든다. 모바일에서는 카드 이미지가 화면 폭에 맞게 줄어들되 원본 비율과 선명도를 유지한다.

## 테스트 전략

### 고화질 자산 회귀

- 78개 카드 파일 모두 존재
- 카드 ID와 이미지 경로가 1:1 대응
- 이미지 크기가 현재 192×288보다 충분히 큼
- 원본보다 임의 확대되지 않음
- 선택 결과 HTML이 실제 `<img>`를 사용하고 스프라이트 배경 좌표를 사용하지 않음

### 타로 기능 회귀

- 카드 총 78장
- 1장/3장 중복 없는 선택
- 정/역방향
- 두 종류의 3장 스프레드
- 기존 로컬 기본 해석이 AI 없이도 작동

### AI API 회귀

OpenAI 실제 과금 호출 없이 `fetch`를 mock한다.

- 유효한 1장 요청 성공
- 유효한 3장 요청 성공
- 존재하지 않는 카드 ID 거부
- 중복 카드 거부
- 잘못된 position/orientation 거부
- 질문 길이 제한
- API 키 미설정 503
- OpenAI 429/5xx 오류 변환
- 성공 응답의 구조 검증
- 프롬프트에 클라이언트가 임의로 보낸 카드 의미를 사용하지 않고 서버 공식 데이터만 사용

### 사이트 회귀

기존 CI의 다음 테스트를 계속 통과시킨다.

- CATCH source regression
- CATCH embed regression
- notice single-board regression
- TAROT feature regression
- TAROT asset regression
- multipage smoke regression

## 배포 요구사항

Vercel Production 환경에 `OPENAI_API_KEY`가 필요하다.

선택적으로 `OPENAI_TAROT_MODEL=gpt-5.6-luna`를 지정할 수 있다. 지정하지 않으면 서버 코드 기본값을 사용한다.

환경변수 설정 전에도 사이트 배포와 기본 타로는 정상 작동해야 하며, AI 상담만 비활성 상태로 처리한다.

## 완료 기준

- 결과 카드가 현재 스크린샷보다 눈에 띄게 선명하다.
- 78장 모두 첨부 원본 이미지와 정확히 대응한다.
- 사용자가 뽑은 카드만 고화질로 로드한다.
- 기존 기본 리딩이 유지된다.
- AI 버튼을 누르면 선택한 카드/방향/스프레드/질문을 반영한 한국어 상담 리딩이 나온다.
- API 키가 클라이언트에 노출되지 않는다.
- AI 장애가 기존 타로 사용을 막지 않는다.
- 기존 공지/CATCH 등 팬사이트 회귀 테스트가 깨지지 않는다.
