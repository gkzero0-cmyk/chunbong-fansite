# 춘봉 콘텐츠 시리즈형 아카이브 재구성 설계

Date: 2026-09-22
Branch: `feat/chunbong-content-series-archive`

## 목적

현재 춘봉 콘텐츠 페이지는 레오펠, 그냥서버: 머니게임, 싸이감성 노래자랑, 춘타클을 각각 하나의 독립 항목으로만 다뤄 실제 방송 기록과 맞지 않는다. 또한 자체 제작한 임시 SVG가 대표 이미지로 노출되고, 페이지 상단의 장식용 카드 영역이 실제 콘텐츠를 보여주지 않아 첫 화면 정보 밀도가 낮다.

이번 개편의 목적은 춘봉이 직접 주최·기획한 콘텐츠를 **시리즈 → 시즌/회차 → 실제 게시글·영상·이미지** 구조로 재정리하고, 대표 이미지를 SOOP 방송국/Notion/YouTube 등 실제 사용 자료 중심으로 교체하는 것이다.

## 확인된 문제

1. **그냥서버**
   - 현재 팬사이트에는 `그냥서버 : 머니게임`만 존재한다.
   - 공개 기록에서 2026-04-09 첫 `그냥서버` 개최 기록이 확인된다.
   - Notion에는 `그냥서버2`가 2026-06-24~2026-07-15로 별도 존재하며, 커버 파일도 붙어 있다.
   - Notion에는 `그냥서버: 적자생존`이 2026-09-30~2026-10-21로 별도 존재한다.
   - 따라서 부모 시리즈 `그냥서버` 아래에 최소 세 시즌을 둬야 한다.

2. **싸이감성 노래자랑**
   - 현재 2026-04-28 개최분 한 회차만 존재한다.
   - 실제로 2회 개최되었으므로 1회/2회를 분리해야 한다.
   - 2회 날짜·참가자·결과는 SOOP/Notion/방송 기록을 수집해 확정한다.

3. **춘타클**
   - 현재 하나의 통합 레코드에 일부 회차만 섞여 있고 1회가 누락돼 있다.
   - Notion에는 `춘타클 1회`, `2회`, `3회`, `4회` 일정이 별도로 존재한다.
   - 일부 Notion 일정과 기존 포스터/팬사이트 기록의 날짜가 충돌하므로, SOOP 게시글과 실제 방송 이력을 최우선 근거로 회차 날짜를 확정한다.
   - 충돌 자료는 삭제하지 않고 운영자 검증 메모로 남긴다.

4. **레오펠**
   - 시리즈 분리는 필요 없지만 자료량에 비해 현재 상세가 지나치게 얇다.
   - SOOP PICK 발표회, 공식 VOD, 트레일러, 서버 오픈 기사, Hotterview 등 공식 자료가 이미 확인된다.
   - 방송국 게시글·모집글·이미지까지 더 수집해 하나의 완성형 아카이브 상세로 확장한다.

5. **목록 첫 화면**
   - 현재 상단 오른쪽은 `POSTER / VOD / ARCHIVE` 임시 장식 카드라 실제 정보가 없다.
   - 콘텐츠 카드 목록은 그 아래에서 시작해 화면 상단이 비어 보인다.

## 선택된 구조: B안 — 시리즈 부모 + 시즌/회차 자식

### 기본 모델

공개 목록의 1차 단위는 **시리즈**다.

- 레오펠
- 그냥서버
- 싸이감성 노래자랑
- 춘타클

시리즈 상세 안에 **시즌/회차**를 둔다.

예시:

```
그냥서버
├─ 그냥서버 1
├─ 그냥서버 : 머니게임
└─ 그냥서버 : 적자생존

싸이감성 노래자랑
├─ 1회
└─ 2회

춘타클
├─ 1회
├─ 2회
├─ 3회
└─ 4회

레오펠
└─ 단일 시즌
```

레오펠은 자식 하나를 억지로 표시하지 않고 단일 콘텐츠 상세로 보인다.

### 부모 시리즈

부모 레코드는 시리즈 공통 소개와 대표 이미지만 가진다. 자식 회차 수, 전체 기간, 총 미디어 수 등은 공개 API에서 자식 레코드를 집계해 만든다.

### 시즌/회차

각 시즌·회차가 다음 정보를 독립적으로 가진다.

- 실제 개최일/기간
- 대표 이미지
- 모집/공지 게시글
- 참가자/수강생
- 결과
- 타임라인
- 다시보기
- Catch
- 클립
- YouTube
- Shorts
- 이미지 갤러리
- 출처

이렇게 해야 같은 이름의 콘텐츠가 여러 번 열려도 자료가 섞이지 않는다.

## 실제 자료 수집 원칙

### 사실 정보 우선순위

1. 춘봉 SOOP 방송국 게시글
2. 춘봉 SOOP VOD / Catch / 클립
3. 춘봉 공식 YouTube / Shorts
4. 연결된 Notion 일정·기획 자료
5. SOOP PICK 및 관계자 공식 방송/게시물
6. `namu.wiki` 원문
7. 기타 외부 방송 이력은 보조 검증만 사용

`namu.moe`, `m.namu.moe`, `d.namu.moe` 같은 미러를 공개 출처명으로 `나무위키`라고 표시하지 않는다. 진짜 `namu.wiki` 원문을 직접 확인할 수 없으면 해당 출처는 생략하거나 보조 검증 메모로만 사용한다.

### 대표 이미지 우선순위

1. 해당 콘텐츠 SOOP 방송국 모집/공지글의 실제 첨부 이미지
2. 실제 VOD/Catch/클립 썸네일
3. YouTube/Shorts 실제 썸네일
4. Notion에 저장된 실제 포스터/커버
5. 관계자 공식 자료
6. 위 자료가 전혀 없을 때만 팬사이트 폴백 이미지

현재 자체 제작 SVG는 삭제하지 않고 폴백으로 남기되 대표 이미지에서는 최대한 제거한다.

### 이미지 영구 저장

SOOP/Notion의 만료성 URL을 페이지에서 직접 사용하지 않는다.

- 접근 가능한 원본을 한 번 수집
- 원본 비율과 화질을 보존
- 팬사이트 저장소 또는 현재 사용하는 영구 이미지 저장소에 보관
- `sourceId`로 원문 출처 연결
- 갤러리의 `원문 보기`에서 최초 게시물로 이동

Notion의 signed S3 URL은 만료되므로 반드시 영구 자산으로 복사한 뒤 사용한다.

## 공개 페이지 UX

### 상단 재구성

현재 `POSTER / VOD / ARCHIVE` 장식 카드 3개를 제거한다.

새 상단은 다음 구조다.

**왼쪽**
- CHUNBONG CONTENT ARCHIVE
- 춘봉 콘텐츠
- 설명
- 시리즈 수 / 시즌·회차 수 / 실제 자료 수 요약

**오른쪽**
- 최신 또는 대표 시리즈의 **실제 대표 이미지**
- 이미지 하단에 콘텐츠명 + 회차/시즌 + 날짜
- 클릭 시 해당 상세로 이동

상단 바로 아래에 4개 대표 시리즈를 작은 비주얼 네비게이션으로 배치해 첫 화면에서 바로 콘텐츠를 볼 수 있게 한다.

검색/필터 툴바와 전체 카드 목록은 이 대표 영역 바로 아래에 붙여 현재의 큰 빈 공간을 없앤다.

### 시리즈 카드

부모 카드에는 다음을 표시한다.

- 실제 대표 이미지
- 시리즈명
- 카테고리
- 춘봉 역할
- 시즌/회차 수
- 전체 기간
- 대표 설명
- `3시즌`, `4회` 같은 배지

### 시리즈 상세

부모 상세는 상단에 시리즈 설명을 보여주고 바로 아래에 시즌/회차 선택 카드를 둔다.

예: 그냥서버

```
[그냥서버 1] [머니게임] [적자생존]
```

선택 시 같은 상세 페이지 안에서 해당 시즌의 기록으로 전환한다. URL은 공유 가능하게:

```
chunbong-contents.html?id=justserver&edition=moneygame
```

### 회차 상세

선택한 회차에 대해 다음 순서로 표시한다.

1. 실제 대표 포스터/썸네일
2. 기간·회차·참가자·자료 수
3. 소개
4. 모집/공지 원문
5. 타임라인
6. 참가자/수강생 및 결과
7. 다시보기 · Catch · 클립
8. YouTube · Shorts
9. 실제 이미지 갤러리
10. 출처

자료가 없는 탭은 빈 탭으로 남기지 않고 숨긴다.

## API

기존 `/api/content` 단일 함수 구조를 유지한다.

### 목록

`type=chunbong-contents`

기본 응답은 부모 시리즈만 반환한다. 각 부모에 집계 필드를 붙인다.

```js
{
  editionCount,
  editionLabels,
  totalMedia,
  totalImages,
  latestEditionId
}
```

### 상세

`type=chunbong-content&id=justserver`

부모와 공개된 자식 회차를 함께 반환한다.

```js
{
  item: parent,
  editions: [...]
}
```

기존 단일 레코드 URL은 가능한 한 호환성을 유지한다.

예:
`?id=justserver-moneygame` 접근 시 부모 `justserver` + `edition=moneygame`로 클라이언트에서 정규화한다.

## 마이그레이션

현재 시드 데이터를 다음처럼 변환한다.

- `leopel` → 부모 시리즈이자 단일 상세
- `justserver-moneygame` → `justserver` 부모의 edition
- `psy-emotion-song-contest-2026` → `psy-emotion-song-contest` 부모의 1회 또는 검증된 회차
- `chuntacle-2026` → `chuntacle` 부모 + 회차별 edition

새 자료를 수집하기 전에는 추측으로 빈 시즌을 published 처리하지 않는다.

## 상충 자료 처리

같은 회차에 서로 다른 날짜가 있으면:

1. SOOP 방송국 공지/게시글
2. 실제 VOD 방송 시각
3. 최종 포스터
4. Notion 일정
5. 외부 방송 이력

순으로 비교한다.

확정할 수 없으면 `needs_review`로 두고 공개 API에서 해당 불확실 값을 확정 사실처럼 표시하지 않는다.

## 완료 기준

1. 공개 목록에서 그냥서버, 싸이감성 노래자랑, 춘타클이 부모 시리즈로 보인다.
2. 그냥서버에서 3개 시즌을 구분할 수 있다.
3. 싸이감성 노래자랑에서 2개 회차를 구분할 수 있다.
4. 춘타클에서 1회부터 확인된 회차까지 각각 볼 수 있다.
5. 레오펠이 공식 게시글·VOD·트레일러·이미지를 가진 풍부한 상세 페이지로 보인다.
6. 임시 SVG가 실제 자료를 대체하지 않는다.
7. 페이지 상단 첫 화면부터 실제 콘텐츠 이미지가 보인다.
8. 모든 사실과 이미지에 추적 가능한 출처가 있다.
9. 출처 충돌은 공개 전에 검증된다.
10. PC/모바일/Production 회귀 테스트가 모두 통과한다.
